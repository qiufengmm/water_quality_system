# 水质监测与预测系统 — 架构设计文档

## 1. 系统架构概述

本系统基于**分层架构 + 模块化设计**思想，采用Python生态技术栈实现。系统自上而下划分为表现层、接口层、业务逻辑层、数据层四层，各层职责单一、层间单向依赖。

```
┌─────────────────────────────────────────────────┐
│                  表现层 (Presentation)            │
│         Vue 3 + Element Plus (Week 2+)          │
├─────────────────────────────────────────────────┤
│                  接口层 (API)                    │
│     FastAPI REST API + JWT Auth (Week 3+)       │
├─────────────────────────────────────────────────┤
│               业务逻辑层 (Business Logic)         │
│  ┌─────────┐ ┌──────────┐ ┌──────────────────┐  │
│  │ 数据采集 │→│ 数据清洗  │→│ 模型训练与预测   │  │
│  └─────────┘ └──────────┘ └──────────────────┘  │
│       ↓              ↓              ↓            │
│  ┌─────────┐ ┌──────────┐ ┌──────────────────┐  │
│  │ 可视化   │ │ 异常告警  │ │ 数据统计与导出   │  │
│  └─────────┘ └──────────┘ └──────────────────┘  │
│  ┌──────────────────────────────────────────┐   │
│  │            系统后台管理                    │   │
│  └──────────────────────────────────────────┘   │
├─────────────────────────────────────────────────┤
│                  数据层 (Data)                   │
│    MySQL 8.0 (结构化) + 时序文件存储 (CSV)       │
└─────────────────────────────────────────────────┘
```

## 2. 核心模块设计

### 2.1 模块职责

| 模块 | 职责 | 开发周次 |
|------|------|----------|
| **多源数据采集模块** | 统一接入CSV/Excel、模拟传感器、手动录入数据 | 第1周 |
| **数据清洗与管理模块** | 去重、缺失值处理、异常检测、数据标准化 | 第1周 |
| **模型训练与水质预测模块** | XGBoost模型训练、1-7天水质预测 | 第2周 |
| **数据可视化展示模块** | 水质图表展示、仪表盘、趋势分析 | 第2周 |
| **水质异常告警模块** | 阈值配置、自动触发告警、告警历史 | 第3周 |
| **数据统计与导出模块** | 统计报表、Excel/PDF导出 | 第3周 |
| **系统后台管理模块** | 账号权限、站点管理、系统配置 | 第3周 |

### 2.2 模块间交互关系

```
数据采集 → 数据清洗 → 模型预测 → 可视化展示
                   ↘         ↗
                  异常告警 ←─┘
                  数据导出 (独立调用数据)
                  后台管理 (为所有模块提供支撑)
```

## 3. 数据流设计

### 3.1 核心数据流

```
传感器/MQTT → JSON → 数据采集模块 → 原始CSV存储
                                              ↓
数据清洗模块 → Pandas DataFrame → 清洗后CSV存储
                                              ↓
ML模型 (XGBoost) → 预测结果 → JSON响应
```

### 3.2 数据格式规范

- **内部传输**: JSON格式，字段名采用snake_case
- **文件存储**: CSV格式，UTF-8编码带BOM
- **时间格式**: ISO 8601 (YYYY-MM-DD HH:mm:ss)

## 4. 技术栈选型

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| Python 3.9+ | 开发语言 | 生态丰富、门槛低、跨平台 |
| FastAPI | Web框架 | 异步性能好、自动API文档 |
| Pandas/NumPy | 数据处理 | 时序数据处理能力强大 |
| Scikit-learn | ML框架 | 简单易用、适合入门 |
| XGBoost | ML算法 | 预测精度高、泛化能力强 |
| Vue 3 + Element Plus | 前端框架 (W2) | 轻量高效、组件丰富 |
| MySQL 8.0 | 结构化存储 | 开源免费、部署简单 |
| Plotly/Matplotlib | 可视化 | 交互式图表、Python原生 |

## 5. API接口设计

### 5.1 第1周接口

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | /health | 健康检查 |
| POST | /api/data/upload | 上传CSV数据文件 |
| POST | /api/data/upload/simulate | 生成模拟传感器数据 |
| POST | /api/data/manual | 手动录入水质数据 |
| GET | /api/data/raw | 查询原始数据 |
| POST | /api/data/clean | 执行数据清洗 |
| GET | /api/data/cleaned | 查询清洗后数据 |
| GET | /api/data/summary | 数据统计摘要 |

### 5.2 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

## 6. 类设计

### 6.1 数据采集层

```
BaseCollector (抽象基类)
├── CsvCollector    — CSV/Excel文件导入
├── SensorCollector — 模拟传感器数据
└── ManualCollector — 手动录入
```

### 6.2 数据清洗层

```
DataCleaner       — 清洗主流水线
WaterQualityValidator — 基于GB 3838-2002标准的校验器
DataTransformer   — 格式转换器
```

### 6.3 数据模型层

```
WaterQualityRecord — Pydantic数据模型
CleaningConfig     — 清洗配置模型
CleaningReportModel — 清洗报告模型
```

## 7. 安全设计

- **身份认证**: JWT Token (Week 3实现)
- **权限控制**: RBAC基于角色的权限管理 (Week 3实现)
- **密码存储**: BCrypt哈希加密
- **注入防护**: SQLAlchemy ORM参数化查询
- **数据加密**: AES-256敏感配置加密
